# 01 · 渲染管线全景（零基础）

> 对应 App 第 01 项 · 难度：入门概念 · 预计阅读 10 分钟

## 你将搞懂

- CPU 和 GPU 在一帧画面里各自的分工
- 一次 `glDrawArrays` 调用内部经过的 7 道工序
- 哪些环节可以编程（写 shader）、哪些只能配置参数
- OpenGL 与 Android View/Canvas 绘制体系的关系

## 先讲人话：GPU 是一家"画三角形的高速工厂"

你写的 Java 代码跑在 **CPU** 上，CPU 是"设计师"：准备好原料（顶点数据）、写好两台可编程机器的加工规则（着色器程序），然后把整批活儿**一次性**交给 GPU 工厂。

GPU 工厂内部是一条**固定顺序的流水线**，共 7 道工序。其中：

- **只有 2 道可编程**（第②站顶点着色器、第⑥站片元着色器）——你写 GLSL 代码；
- 其余 5 道是"固定机器"——不能改逻辑，只能拧旋钮（开关、函数、参数）。

> **Android 类比**：CPU 准备数据 ≈ 你在 `onDraw()` 里准备 Path/Bitmap；GPU 流水线 ≈ 硬件加速的 RenderThread；`eglSwapBuffers` ≈ Choreographer 的 vsync 触发上屏。

## 七道工序总览

| 站 | 名称 | 类型 | 输入 | 输出 |
|---|---|---|---|---|
| ① | 顶点数据 | CPU→GPU | `float[]` 数组 | 显存里的 VBO/VAO |
| ② | 顶点着色器 | **可编程**，每顶点一次 | 顶点属性 + uniform | 裁剪空间坐标 `gl_Position` + varying |
| ③ | 图元装配 | 固定 | 有序顶点流 + drawMode | 三角形/线/点序列 |
| ④ | 裁剪·透视除法 | 固定 | 裁剪空间图元 | NDC 坐标 `[-1,1]` |
| ⑤ | 视口变换·光栅化 | 固定 | NDC 图元 | 片元（含插值属性、深度） |
| ⑥ | 片元着色器 | **可编程**，每片元一次 | 插值后的 varying、纹理 | RGBA 颜色 |
| ⑦ | 测试·混合 | 固定 | 片元 + 帧缓冲现有值 | 屏幕像素 |

数据自上而下单向流动，任何一站都可能"减员"（剔除、裁剪、测试失败），但绝不回头。

## 一次 draw call 的完整旅程（文字版时序）

```text
CPU:  float[] data ──glBufferData──▶ 显存VBO ──配置──▶ VAO
CPU:  编译/链接 VS+FS ──▶ GPU 程序 (program)
CPU:  glDrawArrays(GL_TRIANGLES, 0, 3)        ← 一条命令提交整批
──────────────────────── 进入 GPU 流水线 ────────────────────────
②   VS 对 3 个顶点各执行一次，算出裁剪空间位置
③   装配成 1 个三角形；背面剔除检查
④   视锥外部分被裁剪；坐标除以 w 得 NDC
⑤   光栅化铺成 N 个片元，v_color 自动插值
⑥   FS 对 N 个片元各执行一次，算出颜色
⑦   深度测试 → 混合 → 写入帧缓冲
CPU:  eglSwapBuffers()  后缓冲↔前缓冲交换，画面出现
```

## 和 Android View 绘制体系的关系

| Android View 体系 | OpenGL 对应 |
|---|---|
| `View.onDraw()` 里的 Canvas 指令 | CPU 提交的 draw call |
| `View.translationX/rotation/scale` | Model 矩阵（见第 12/29 章） |
| 硬件加速 RenderThread | GPU |
| `Choreographer` vsync | 帧调度 / `eglSwapBuffers` |
| `Bitmap`（像素阵列） | 帧缓冲的颜色附件 |

核心区别：**Canvas 是"逐条指令"画（retained 顺序执行）**，OpenGL 是"整批数据交给并行工厂"（数据驱动）。所以 GL 的思维是：把状态设置好 → 一次性提交大批数据 → 让几千个 GPU 核心并行处理。

## 在 App 里怎么玩（第 01 项）

- 界面是一条自上而下的流水线图：**橙色节点=可编程**（你要写 GLSL 的地方），**蓝色=固定功能**（只能配参数），**灰色=CPU 侧**；
- 黄色方块是"数据包"，沿流水线流动，到哪站哪站亮；
- **点按任意节点**：高亮该站，并自动跳到底部【代码】页签的对应代码段——跟着从 ① 读到 ⑦，GPU 的工作方式就通了。

## API 速查

| API | 作用 |
|---|---|
| `glBufferData` | 把 CPU 数据整批拷进显存 |
| `glDrawArrays / glDrawElements` | 提交一批顶点进入流水线 |
| `glViewport` | NDC → 窗口像素的映射 |
| `eglSwapBuffers` | 前后缓冲交换，画面上屏 |

## 常见坑

- **以为 FS 是逐三角形执行的**：FS 逐片元执行，全屏三角形=百万次；能放 VS 的计算别放 FS。
- **以为 GLES 调用是立即执行的**：大多数只是"记录命令"，真正执行在 GPU 流水线上，出错要靠 `glGetError()` 查。
- **混淆"片元"和"像素"**：片元是候选像素（还没通过第⑦站测试），通过了才成为像素。
