# 04 · 光栅化：三角形怎么变成像素

> 对应 App 第 04 项「第3站·光栅化放大镜」· 难度：入门概念

## 你将搞懂

- 片元（fragment）和像素的区别
- 光栅化插值：顶点色渐变为什么是"白送的"
- 重心坐标插值与透视校正
- 中心采样规则——锯齿的根源

## 先讲人话

顶点着色器只给出 3 个"屏幕坐标点"，**光栅化**负责把三角形"铺"成像素：找出三角形覆盖了哪些像素格，每个被覆盖的格生成一个**片元（fragment）**。

> **术语**：片元 = 候选像素。它还要过第⑦站测试，通过了才真正成为像素。

> **Android 类比**：`VectorDrawable` 矢量图光栅化成 `Bitmap` 位图——矢量是连续数学描述，位图是离散像素阵列。OpenGL 光栅化干的就是"矢量→位图"这一步，只是每帧都在发生。

## 原理图：中心采样与插值

```text
 三角形（连续的数学面）            光栅化后（离散的像素阵列）
                              ┌───┬───┬───┬───┬───┐
         ╱▔▔╲                 │ ▒ │ ▒ │▒▒▒│▒▒▒│   │   每格 = 一个片元
        ╱   ▏                 ├───┼───┼───┼───┼───┤   ▪ = 像素中心（采样点）
       ╱    ▏                 │ ▒ │ ▒▒│▒▒▒│   │   │   颜色 = 重心坐标
      ╱     ▏                 ├───┼───┼───┤   │   │   加权 (w1,w2,w3)
     ╱______╱                 │▒▒▒│▒▒▒│   │   │   │
                              └───┴───┴───┴───┴───┘
                              只有中心点落在 ▲ 内的格子才生成片元
                              → 边缘格子二选一 → 锯齿的来源
```

App 第 04 项第 3 行把这些格子画出来，颜色就是 CPU 用重心坐标算的插值——
和 GPU 每帧干的事一模一样，只是"慢放"了。

## 插值：渐变是白送的

三个顶点各带颜色（红/绿/蓝），光栅化硬件对每个片元自动计算"三个顶点各占多少权重"（**重心坐标** w1/w2/w3，和为 1）：

```text
片元颜色 = w1×v0颜色 + w2×v1颜色 + w3×v2颜色
```

离哪个顶点近哪个权重大 → 自然渐变。这一步发生在片元着色器**之前**，不花你一行代码。所有 `out` 顶点变量（颜色、uv、法线…）都这样插值，纹理不扭曲也是它的功劳——插值是**透视校正**的（先除以 w 插值再乘回来）。

## CPU 模拟版（App 第 04 项第 3 行干的事）

```java
// 对放大区域 n×n 个格子，每格取【中心点】采样一次：
for (int j = 0; j < n; j++) {
    for (int i = 0; i < n; i++) {
        float wx = x0 + (i + 0.5f) * (x1 - x0) / n;   // 格子中心的世界坐标
        float wy = y0 + (j + 0.5f) * (y1 - y0) / n;
        // 重心坐标判定覆盖 + 插值颜色
        float det = (y2 - y3) * (x1 - x3) + (x3 - x2) * (y1 - y3);
        float w1 = ((y2 - y3) * (wx - x3) + (x3 - x2) * (wy - y3)) / det;
        float w2 = ((y3 - y1) * (wx - x3) + (x1 - x3) * (wy - y3)) / det;
        float w3 = 1f - w1 - w2;
        boolean covered = w1 >= 0 && w2 >= 0 && w3 >= 0;  // 都≥0 = 在三角形内
        // 整格填 covered 决定的颜色（插值色或背景色）
    }
}
```

这就是 GPU 每帧对百万像素并行干的事——App 里用 CPU 循环"慢放"给你看。

## 中心采样规则：锯齿的根源

一个像素算不算被三角形覆盖？OpenGL 默认规则是**中心采样**：像素**中心点**落在三角形内才算覆盖。于是边缘处出现"一半在内一半在外"的格子只能二选一 → 台阶感（锯齿）。

解法预告：MSAA 在一个像素里放 4~8 个采样点再平均（第 31 章）。

## 在 App 里怎么玩（第 04 项）

三行视口从上到下：

1. **正常视图**：渐变三角形，白框是放大区域；
2. **GPU 放大渲染**：同一区域变焦后——连续平滑毫无瑕疵；
3. **CPU 模拟光栅化**：同一区域切成 n×n 小方块，每格只取中心点一次颜色。

**实验**：
- 对比行 2 和行 3 → 真相大白：所谓平滑渐变，其实是小方块各自一种颜色；
- 拖 **网格密度** 滑条（6~26）：格子越少越马赛克，越多越平滑——这就是"分辨率"的含义；
- **在第一行拖动手指**：放大区域跟随移动，注意行 2/3 实时刷新；
- 打开 **显示采样点**：每格中心的小黑点就是采样点。

## API 速查

光栅化本身没有 API（纯硬件），相关配置只有：

| API | 作用 |
|---|---|
| `glViewport` | NDC → 窗口像素映射 |
| `glEnable(GL_MULTISAMPLE)` | 启用多重采样（第 31 章） |

## 常见坑

- **以为渐变是 FS 算出来的**：插值是光栅化硬件做的，FS 只是"收到"插值结果。
- **顶点数太少的低模放大看**：插值颜色正确但几何边缘是折线——插值救不了几何。
- **跨越大距离的插值精度**：mediump 下 uv 插值可能出现条纹，关键量声明 highp。
